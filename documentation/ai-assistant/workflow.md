# 🔄 Workflow de Développement Autonome

Ce guide décrit la procédure stricte que l'IA doit suivre pour développer de manière autonome.

## 📚 Références

- **Tests manuels détaillés** : [`manual-testing-guide.md`](manual-testing-guide.md)
- **Stratégie tests** : [`testing.md`](testing.md)
- **Architecture** : [`architecture.md`](architecture.md)
- **Plan développement** : [`features.md`](features.md)

---

## 🚀 Commandes Principales

### 1. "Continue le développement"

Quand l'utilisateur dit **"continue le développement"** ou équivalent :

1. **Ouvrir `features.md`** et trouver le marqueur `📍 POSITION ACTUELLE`
2. **Lire le groupe de features actuel** (toutes les sous-tâches)
3. **Vérifier le code existant** pour chaque item (beaucoup existe déjà)
4. **Implémenter ou corriger** ce qui manque
5. **Créer/exécuter les tests** listés sous "🧪 Tests Phase X.X"
6. **Mettre à jour `features.md`** : cocher [x] et déplacer 📍 si nécessaire
7. **Commit** et continuer au prochain groupe si terminé

---

### 2. "Execute l'ensemble des tests"

Quand l'utilisateur dit **"execute l'ensemble des tests"**, **"run all tests"**, **"test everything"** ou équivalent :

#### 🔁 Processus avec Itération Automatique sur les Erreurs

**⚠️ CRITIQUE** : L'IA DOIT itérer automatiquement sur les erreurs jusqu'à ce que TOUS les tests passent. Ne JAMAIS s'arrêter après avoir détecté des erreurs sans les corriger.

```
BOUCLE PRINCIPALE (répéter jusqu'à ce que TOUS les tests passent) :
│
├─ 1. TESTS UNITAIRES
│  ├─ Exécuter : npm run test:extension
│  ├─ Si échec :
│  │  ├─ Lister TOUS les tests qui échouent avec détails complets
│  │  ├─ Analyser chaque erreur (message, stack trace, fichier concerné)
│  │  ├─ Identifier la cause racine
│  │  ├─ Corriger le code
│  │  └─ RETOURNER à l'étape 1 (re-tester)
│  └─ Si succès : continuer à l'étape 2
│
├─ 2. BUILD EXTENSION
│  ├─ Exécuter : npm run build:extension
│  ├─ Si échec :
│  │  ├─ Lister TOUTES les erreurs TypeScript/compilation
│  │  ├─ Analyser chaque erreur (fichier, ligne, type d'erreur)
│  │  ├─ Corriger le code
│  │  └─ RETOURNER à l'étape 2 (re-build)
│  └─ Si succès : continuer à l'étape 3
│
└─ 3. TEST POPUP DANS NAVIGATEUR
   └─ (voir détails ci-dessous avec boucle d'itération)
```

**3. Test Popup dans Navigateur**

**MÉTHODE OBLIGATOIRE** : Mode Web + Navigateur MCP Cursor

**⚠️ IMPORTANT** : Pour les tests web de la popup, l'IA DOIT utiliser UNIQUEMENT le navigateur MCP de Cursor.

**Processus** :
- Démarrer serveur web : `npm run dev:web`
- Naviguer vers popup : `http://localhost:3000/packages/extension/popup/index.html`
- Tester avec navigateur MCP Cursor
- **BOUCLE D'ITÉRATION** : Corriger → Re-tester jusqu'à ce que TOUT fonctionne

**Voir guide détaillé** : `documentation/ai-assistant/manual-testing-guide.md` section "Méthode Standard"

**4. Tests Popover (Content Scripts) avec MCP Playwright**

**⚠️ QUAND UTILISER** : Pour tester les popovers nécessitant l'extension réelle.

**Processus** :
- Build extension : `npm run build:extension`
- Lancer Chromium avec extension (MCP Playwright, non-headless)
- Tester popover sur page signup/login
- **BOUCLE D'ITÉRATION** : Corriger → Rebuild → Re-tester jusqu'à ce que TOUT fonctionne
- **CRÉER TESTS AUTOMATISÉS** : Créer `packages/extension/__tests__/playwright/XX-feature-name.spec.ts`

**Voir guide détaillé** : `documentation/ai-assistant/manual-testing-guide.md` section "Tests Popover"

## 🔁 La Boucle d'Itération (The Loop)

Pour chaque **groupe de features** (ex: 0.1, 0.2, 1.1, etc.) :

### 1. Analyse & Vérification
```
📌 AVANT d'implémenter quoi que ce soit :
```
*   Lire TOUTES les sous-tâches du groupe actuel
*   Pour chaque item marqué `[~]` ou `[ ]` :
    *   Vérifier si le fichier/code existe déjà
    *   Si oui : évaluer s'il est complet ou à corriger
    *   Si non : planifier l'implémentation
*   Vérifier l'architecture dans `architecture.md`

### 2. Développement (Web Mode First)
```bash
npm run dev:web
```
*   Créer/Modifier les composants dans `packages/extension/ui`
*   Utiliser la **Sandbox** (`/sandbox`) pour tester les Popovers
*   Vérifier que la logique fonctionne avec le `browserAPI` shim
*   **Terminer TOUTES les sous-tâches du groupe**

### 3. Intégration (Extension Mode)
```bash
npm run build:extension
```
*   S'assurer que le build passe sans erreur TypeScript
*   Vérifier que les fichiers `dist/` sont générés

### 4. Tests (Obligatoire)
Implémenter ET faire passer les tests listés dans `features.md`.

```bash
npm run test:extension      # Tests unitaires
```

*   Si échec : lire les logs, diagnostiquer, corriger, recommencer
*   Si succès : passer à l'étape 5

### 5. Mise à jour & Commit
*   **Mettre à jour `features.md`** :
    *   Cocher `[x]` pour chaque item terminé
    *   Cocher `[x]` pour chaque test passé
    *   Déplacer `📍 POSITION ACTUELLE` au prochain groupe si terminé
*   **Commit** : `feat(scope): description` ou `fix(scope): description`
*   **Continuer** au prochain groupe

**Processus** :
```bash
# 1. L'IA doit D'ABORD démarrer le serveur web

#    - Tester les features de la phase (clics, formulaires, etc.)
#    - Vérifier les logs en temps réel (browser_console_messages)
#    - Itérer : corriger → HMR recharge automatiquement → re-tester jusqu'à ce que ça fonctionne

**Checklist automatisée (Mode Web)** :
- [ ] **Serveur web démarré** : `npm run dev:web` (l'IA doit exécuter cette commande)

- [ ] Aucune erreur console (`browser_console_messages` avec level='error')
- [ ] Features de la phase fonctionnent (voir checklist spécifique dans `manual-testing-guide.md`)
- [ ] Itération : Si erreur détectée → corriger → HMR recharge → re-tester
- [ ] **Nettoyage** : Arrêter le serveur web après les tests (`lsof -ti:3000 | xargs kill -9`)

Dans `features.md`, cocher la section **"✅ Validation Phase X"** :

- [ ] Test popup automatisé réussi (via navigateur MCP Cursor)
- [ ] Aucune erreur console détectée
- [ ] Features fonctionnelles (vérifiées via tests automatisés)

#### 5. Si Validation Échoue

**NE PAS continuer** à la phase suivante :
1. Identifier les problèmes
2. Corriger les bugs
3. Re-tester
4. Re-valider

#### 6. Si Validation Réussit

*   **Commit de validation** : `chore(phase-X): validation inter-phase complète`
*   **Continuer** à la phase suivante

Phase 0 terminée → Validation requise :

   - Extension se charge ✅
   - Pas d'erreur console ✅
   - Architecture respectée ✅
5. Cocher "✅ Validation Phase 0" dans features.md
6. Commit: chore(phase-0): validation inter-phase

```

## ⚠️ Règles Critiques
